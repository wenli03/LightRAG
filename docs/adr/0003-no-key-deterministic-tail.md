# ADR 0003 · 降级链的末级是"确定性摘录"，并且必须自我标注

- 状态：已接受
- 日期：2026-09-29

## 背景

任何对外演示的系统都会遇到这三种情况：断网、没有模型 Key、额度用完。
这时的常见做法是报错页或者"稍后再试"，代价是**演示在关键时刻挂掉**——
而演示挂在关键时刻，恰恰是这类项目最致命的失败方式。

另一条路是在链尾放一个不依赖网络的兜底：本地小模型，或者纯规则的摘录。
本地小模型的问题是需要下载权重、需要 CPU 推理、首次启动几十秒到几分钟，
在免费托管环境的冷启动上不可接受；纯规则摘录则完全不依赖网络与算力。

## 决策

降级链固定为四级：**主模型 → 备模型 → 本地模型 → 确定性摘录**，其中：

1. 末级实现为 `enterprise/offline.py::DeterministicExtractive`：它**不生成**，
   只从检索到的原文里按与问题的词元重叠度摘句子，并强制带上引用编号；
2. 末级的输出**第一行就自我标注** `[无模型模式·确定性摘录]`，并说明"以下内容由原文片段直接摘录，未经模型改写"；
3. 末级在"检索到的片段里没有任何句子与问题有词元重叠"时**明确说"不作答"**，
   而不是硬摘一句无关的话充数；
4. 每次回答都返回"实际生效的层级"（`FallbackOutcome.layer`）与"是否降级"（`degraded`），
   网关把它作为响应字段返回——**降级必须对使用者可见**。

## 理由

- **可用性不再依赖第三方**。断网、无 Key、无额度时，全流程（检索 → 门槛 → 作答 → 引用 → 记账 → 审计）走得完。
  这条性质可以直接用测试证明（`test_deterministic_tail_works_without_any_model`）。
- **不标注的降级比降级本身更糟**。一个不标注的规则回答，会被读成"模型答得这么差"；
  一个标注了的降级，读出来的是"产品在模型不可用时仍然可用"。**同一段输出，评价完全不同。**
- **它同时是评测的底座**。因为末级零依赖、完全确定，评测可以在没有模型的环境里跑，
  于是"阈值取多少"这件事可以在烧任何 token 之前就标定出来。

## 代价

1. **观感**：摘录式回答不如生成式流畅，且会显得啰嗦（带引用块与自我标注）；
2. **评测必须区分两种口径**：项目里有两套数字，不能混着说——
   - **零模型离线评测**（`python -m enterprise.eval.run_eval`）：只测"检索 + 护栏"，
     可以在任何环境复跑，`data/eval_report.json` 就是它的产物；
   - **端到端评测（需模型）**：上游自带的 RAGAS 脚本属于这一档，需要真实模型与网络。
3. **误用风险**：有人可能会把"离线评测的 Recall 很高"当成"问答质量很好"来宣传。
   对策是把这个区分写进 README 与评测报告本身，并且在报告里写明
   **语料与 golden set 出自同一作者，因此这组数字衡量的是链路正确性，不是泛化能力**。
